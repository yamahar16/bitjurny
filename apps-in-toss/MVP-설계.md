# 하루 한 문제 상식 퀴즈 — MVP 설계

> 결정 사항: **주제 = 일반 상식**, **외부 채널 없음** → 토스 안에서만 사용자를 모아야 해요.
> 그래서 이 설계의 핵심은 **"친구에게 문제 내기" 공유 루프**와 **매일 돌아오게 만드는 연속 기록**이에요.

---

## 1. 한 줄 콘셉트
**"하루 딱 한 문제, 30초면 끝나는 상식 퀴즈. 맞히면 도장 하나."**

이름 후보: `오늘의 상식` / `상식 한 입` / `하루상식` / `상식도장`
(콘솔 등록 전에 토스 검색에서 같은 이름이 있는지 확인)

## 2. 일반 상식으로 차별화하는 방법
일반 상식 퀴즈는 흔해요. 문제 자체로는 차별화가 어렵기 때문에 **경험**으로 차별화해요.

| 차별화 | 내용 | 왜 중요한가 |
|---|---|---|
| **딱 하루 1문제** | 더 풀고 싶어도 내일 와야 함 (보너스 문제는 광고 보고 1개) | 아쉬움이 재방문을 만들어요 |
| **친구에게 문제 내기** | 내가 푼 문제를 링크로 보내면 친구가 같은 문제를 풀고 "친구는 맞혔대요" 비교 | 채널이 없으니 이게 유일한 바이럴 엔진 |
| **요일별 주제** | 월 역사 · 화 과학 · 수 우리말 · 목 경제 · 금 생활 · 토 세계 · 일 고난도 | 매일 새로운 느낌, 친구에게 보낼 거리 |
| **도장 달력** | 맞힌 날마다 도장. 연속 기록과 칭호 (상식 새싹 → 상식왕) | 모으는 재미, 끊기 아까운 기록 |
| **해설이 재밌음** | 정답 후 2~3줄 "알고 나면 말하고 싶은" 해설 | 공유하고 싶게 만드는 건 문제보다 해설 |

## 3. 핵심 흐름

```
[토스에서 진입] → 오늘의 문제 (4지선다)
                     ↓ 선택
                 결과 + 해설 + 연속 기록 🔥
                     ├─ [친구에게 이 문제 내기] → 공유 링크
                     ├─ [광고 보고 보너스 문제] → 보너스 1문제
                     └─ [내 도장 달력]

[친구가 링크로 진입] → "친구가 낸 문제예요" → 풀기 → "친구는 맞혔어요 / 틀렸어요" 비교
                     → 오늘의 문제도 풀어보기 (신규 사용자 전환)
```

## 4. 화면 구성 (4개)

1. **오늘의 문제 (첫 화면)**
   - 날짜, 오늘의 주제 태그, 연속 기록 🔥 N일
   - 문제 + 보기 4개 (큰 버튼)
   - 이미 풀었으면 → 결과 화면으로 바로 이동
2. **결과**
   - 정답/오답 표시, 해설
   - 주요 버튼 1개: `친구에게 이 문제 내기`
   - 보조 버튼: `광고 보고 보너스 문제 풀기`, `도장 달력 보기`
   - 하단 배너 광고 (문제 화면에는 넣지 않음 — 잘못 누르기 쉬움)
3. **도장 달력**
   - 월간 달력에 맞힌 날 도장, 틀린 날은 빈 칸
   - 누적 정답 수, 최장 연속 기록, 현재 칭호
4. **친구 도전 (공유 링크로 들어온 경우)**
   - "친구가 낸 문제예요" → 풀기 → 비교 결과 → `오늘의 문제 풀러 가기`

## 5. 기술 구조 (서버 없음)

- **문제 데이터**: 앱 번들 안에 JSON으로 포함. 날짜 → 문제 번호로 고정해서 모든 사용자가 같은 날 같은 문제를 풀어요.
  - 출시 시 최소 **180문제(6개월분)** 준비. 문제 추가는 새 번들 업로드(재검수)로 해요.
- **기록 저장**: 앱인토스 `Storage` (기기에 저장, 서버 불필요)
- **친구 도전 링크**: `getTossShareLink('intoss://<앱이름>/challenge?q=<문제번호>&r=<맞힘여부>')`
  → 링크 안에 문제 번호와 결과만 담아서 서버 없이 비교 가능
- **광고**: 보상형(보너스 문제), 배너(결과 화면 하단)
- **화면**: 순수 HTML/CSS/JS + Vite (가볍고 빠르게 열려야 추천 기준의 '성능' 통과)

### 서버가 없어서 못 하는 것 (2단계 후보)
- "오늘 이 문제 정답률 37%" 같은 전체 통계 → 공유하기 매우 좋은 기능이지만 서버 필요
- 친구 랭킹, 문제 오류 신고 접수
- → 사용자 반응을 본 뒤 서버(예: Supabase)를 붙여서 추가

## 6. 수익화

| 광고 | 위치 | 사용자 입장 |
|---|---|---|
| 보상형 | "광고 보고 보너스 문제 1개" | 더 풀고 싶은 사람만 자발적으로 봄 (단가 가장 높음) |
| 배너 | 결과 화면, 도장 달력 하단 | 흐름 방해 없음 |
| 전면형 | **MVP에서는 안 씀** | 예상 못 한 전면 광고는 검수 반려 사유 |

- 사업자 등록 없이 광고 시작 가능 (누적 예상수익 5천 원까지 유예). 그 이후 정산받으려면 사업자 등록 필요.

## 7. 꼭 알아야 할 제약 (조사 결과)

1. **푸시 알림으로 "오늘의 문제가 도착했어요"는 보내기 어려워요.**
   앱인토스 푸시는 결제·예약 같은 기능성 메시지만 허용하고, 서비스 이용 유도·리텐션 목적은 금지예요. → 재방문은 푸시가 아니라 **연속 기록과 공유**로 만들어야 해요.
2. **토스 포인트 프로모션은 사업자 등록 + 최소 5만 원 충전이 필요해요.**
   "첫 문제 풀면 포인트" 같은 참여형은 가능하지만, "정답 맞히면 포인트"처럼 결과 기반 보상은 불가. → MVP 출시 후 반응 보고 결정.
3. **게임으로 분류되지 않게 해요.**
   점수 경쟁·랭킹·승패 요소를 강하게 넣으면 게임물로 볼 수 있어요. 비게임(교육·상식)으로 등록하고, 랭킹은 MVP에서 빼요. 애매하면 등록 전에 앱인토스 채널톡으로 확인해요.
4. **문제 정확성**: 틀린 정답·해설은 리뷰 평점에 바로 영향을 줘요. AI로 초안을 만들더라도 문제마다 출처 확인이 필요해요.
5. **비게임 체크리스트**: 라이트 모드, 핀치 줌 막기, 첫 진입 시 바텀시트 금지, 토스 내비게이션 바 사용 등.

## 8. 일정 (1인 기준 약 2주)

| 기간 | 할 일 |
|---|---|
| 1~3일 | 화면 4개 개발 + 로컬 기록 저장 |
| 4~5일 | 공유 링크(친구 도전), 광고 연동 |
| 3~7일 (병행) | 문제 180개 작성·검수 (요일별 주제 × 약 26주) |
| 8~9일 | 콘솔 등록(앱 정보, 아이콘, 스크린샷), 토스앱 테스트 |
| 10일~ | 검수 요청 (영업일 2~3일) → 출시 |

## 9. 성공 지표 (출시 후 첫 4주)
- **D1 재방문율**: 다음 날 다시 푼 사용자 비율 (목표 30% 이상)
- **공유율**: 문제를 푼 사용자 중 공유한 비율 (목표 10% 이상)
- **친구 링크 → 신규 사용자 전환율**
- 이 지표가 좋으면 → 추천 미니앱 → 부스팅 미니앱으로 노출이 커져요.
